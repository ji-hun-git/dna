# Synthetic fixtures only

## Overview

The repository processes no real health data. Every fixture must be obviously synthetic to a reader, deterministic to a machine, and impossible to confuse with a person or an institution.

## Rules

1. Generate document bytes in code (see `buildSyntheticPdf` in `apps/web/playwright.foundation.config.ts`); do not commit PDFs, images of documents, DICOM, CSV exports, or genetic files.
2. Mark synthetic content in the bytes and the name: PDF comment `%GC-SYNTHETIC-ONLY`, provider names starting `예시`, codes starting `DEMO-`, subjects matching `^synthetic-[a-z0-9-]+$`.
3. Digests: compute the lowercase SHA-256 in the test or config from the generated bytes; never paste a digest whose source bytes are not in the repository.
4. Candidate values live in `SyntheticCandidateFixture` (Spring) and are ordered by `ordinal`; `sourceTextSha256 = sha256("label|value|unit|observedOn")`. Add a set by extending that object and its unit test, then update the browser lifecycle spec.
5. No real names, phone numbers, addresses, resident registration numbers, hospital names, or lab names. Addresses end with `합성 주소`; telephone values are null.
6. Values must not be chosen to imply a clinical story (no "high" cholesterol narrative). Pick unremarkable numbers and keep units exact.
7. Research metadata snapshots (`apps/research-web/tests/fixtures/research-data/`) hold public metadata only, with the retrieval date and rights status recorded in the fixture.

## Where fixtures live

| Kind | Location |

## Before reporting

Run `pnpm security:runtime-policy` and the area gates; grep the diff for `.pdf`, `.dcm`, `.vcf`, `.csv`, `@`, `010-`, and six-digit-plus-seven-digit patterns; confirm every new string is marked as an example in Korean.

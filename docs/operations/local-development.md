# Local development on a workstation

Updated: 2026-09-07. Applies to Windows and macOS/Linux; toolchain examples use Git Bash, the local product example uses PowerShell.

## Run the actual unified synthetic product

Prerequisites: pinned Node/pnpm, Java 21, installed dependencies, and a **dedicated
synthetic-only** loopback PostgreSQL 16+ database with local trust authentication
for `postgres`. Do not reuse your application, research, or real-data database.
The runner applies the repository's normal migrations; it never resets the database.

From the repository root, in PowerShell (replace the example database and working
directory with your dedicated local ones):

```powershell
$env:GC_LOCAL_SYNTHETIC_ONLY = 'yes'
$env:GC_LOCAL_POSTGRES_URL = 'jdbc:postgresql://127.0.0.1:5432/gc_synthetic_demo'
$env:GC_LOCAL_QUARANTINE_ROOT = 'C:/gc-synthetic-demo/quarantine'
pnpm dev:synthetic
```

On macOS/Linux, set those same environment variables using `export` and use an
absolute local quarantine directory. The launcher is cross-platform code; this
change's live launcher smoke is Windows only, not a macOS/Linux execution claim.

Open `http://127.0.0.1:3138` when the runner prints ready. Ports 8087/8091/3138 must
be free; existing processes are not adopted or stopped. Ctrl+C stops only the three
children started by this command; PostgreSQL and generated synthetic files remain.
No Docker service, cloud account, login application or medical-model key is created.
Provider/research/model configuration is not forwarded to the child processes.

1. Select **체험 시작**, then **결과지 추가** and explicit processing consent.
2. Choose **7월 예시 결과지로 시작**; inspect the approved source preview.
3. Confirm, correct or exclude each candidate. Open **기록**, then **진료 준비**.
4. Add the January example to see two dates for the same items. Source links return
   to those current records, not an unrelated static history.
5. Reload to verify persistence, or use **데이터** to revoke consent/delete this
   synthetic profile. Deletion is real for these local synthetic rows/files.

The two source PDFs are generated by the same function used in browser tests.
The server still selects **fixed fixture values**, not text extraction/OCR. The
scanner result and worker image digest are explicitly synthetic substitutes.
Only the exact generated digests are accepted. Do not upload real result files.
The default session lasts 30 minutes and has no account-recovery mechanism; a new
session creates a new owner after expiry/cookie loss. Restarting processes does not
turn this into a long-term identity system. The bootstrap limit is 20 new owners
per minute and 1,000 per database lifetime, including deleted owners; capacity
exhaustion requires operator attention, not repeated retries.

The old integrated-UI environment flag no longer selects a different product.
Without the configured core API and opt-in bootstrap, the frontend does not fall
back to memory-demo success. `pnpm foundation:e2e` remains the destructive test
harness: use its separate `GC_TEST_*` database and never run it on this demo database.

## Toolchain without changing the global Node

The repository pins Node `24.20.0` and pnpm `11.20.0`. If the global Node differs, obtain the exact binary without a global install:

```bash
npx -y node@24.20.0 -v                      # downloads the pinned binary once, prints v24.20.0
NODE24="$(npx -y node@24.20.0 -e "console.log(require('path').dirname(process.execPath))")"
mkdir -p ~/.gc-node24 && cp "$NODE24/node.exe" ~/.gc-node24/   # on macOS/Linux copy "$NODE24/node"
export PATH="$HOME/.gc-node24:$PATH"
corepack enable --install-directory ~/.gc-node24              # creates pnpm shims next to the binary
node -v && pnpm -v                                             # v24.20.0 / 11.20.0
pnpm install --frozen-lockfile
pnpm security:runtime-policy                                   # must print PASS with node=24.20.0
```

Do not weaken `scripts/security/check-runtime-policy.mjs` to match a workstation.

## What runs where

| Gate | Local | Notes |
|---|---|---|
| `pnpm web:test`, `pnpm research:test`, builds | yes | ~25 s and ~5 s |
| `pnpm release:readiness:validate` | yes | exits 0 while the file is valid; `pnpm release:readiness` exits 1 while `NO_GO` |
| `./gradlew.bat test --no-daemon` | partly | the PostgreSQL-backed classes (`*PostgresIntegrationTest`, `ConsentJdbcRepositoryTest`, `SyntheticFhirEvidenceProjectorTest`) skip unless Docker (Testcontainers) or `GC_TEST_POSTGRES_URL` is available |
| `pnpm foundation:e2e` | needs PostgreSQL | requires `GC_TEST_POSTGRES_URL` and `GC_TEST_QUARANTINE_ROOT`; starts Spring, the worker, and Next on loopback |
| ClamAV adapter test | CI only | needs the checksum-verified engine from `.github/workflows/ci.yml` |

To run the PostgreSQL-backed classes locally, point `GC_TEST_POSTGRES_URL` at any PostgreSQL 16+ instance with trust auth on a throwaway database, for example `jdbc:postgresql://127.0.0.1:5432/postgres`. Never point it at a database that holds anything but synthetic data.

## Worktrees

The repository is used with several git worktrees (one per branch). Check `git worktree list` before creating a branch; a branch checked out in another worktree cannot be checked out again.

## What a green local run proves

Only the stated synthetic contract on this machine. CI on `main` is the evidence of record; state which classes skipped in any report.

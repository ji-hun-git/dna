## PR 7a — parser honesty, value contract, idempotency/concurrency/state, hand-labelled fixtures

Branch `codex/wave13-backend-hardening` (HEAD `a30db43`, stacked on `codex/wave11-alive-home`). Tasks 1–13 (spec §2, §3, §4, §9). Synthetic only. Release remains NO_GO; no readiness gate or verdict changed by this PR. Gates were run on 2026-09-19.

### What 7a built

- **Worker — no silent drop (§2).** `NativeTextExtractionProvider.parseRow` never returns `null`: a labelled numeric row either becomes a candidate or one of exactly seven closed abstention reasons (`unreadable`, `ambiguous_value`, `ambiguous_unit`, `missing_evidence`, `qualified_value`, `qualitative`, `previous_column`); a row with no label before its first numeric token (page numbers, institution lines) is `RowParse.Skipped`, not an abstention. Row grammar: value-before-label, glued units (`5.6%`, `188mg/dL`), `<`/`≤`/`>` qualified values → `qualified_value` (the printed comparison is never stored as a number), qualitative results (음성/양성/정상/이상) → `qualitative`. `혈압 120/80 mmHg` splits into two candidates labelled `혈압(수축기)`/`혈압(이완기)` (resolving to `systolic-blood-pressure`/`diastolic-blood-pressure` via two new catalogue aliases), with the printed label `혈압` carried on both as `originalLabel` end to end (candidate → confirmed record → health event → export).
- **Worker — positional columns and dates.** `PositionalLineGrouper` reconstructs same-baseline multi-column rows by x-gap token grouping instead of raw `PDFTextStripper` order; a previous-result column is only recognized when a real header (이전/전회/직전 or a year) sits above it (`previous_column`) — a headerless duplicate value in a second column stays the honest `ambiguous_value`, not a silently-accepted second candidate. Labels that continue onto a following line are joined before parsing. Date rules: Korean compounds (재검사일 등) excluded by lookaround, English `report`/`print`/`printed`/`issue`/`issued`/`reported`/`generated`/`received` prefixes excluded from the exam-date label, `검사일자` now covered, two-digit years remain unsupported (stated, not silently wrong).
- **Core — value contract (§3, founder decision 1).** `CandidateConfirmationRequest.value` and `RecordCorrectionRequest.value` now accept the worker's own grammar (`^-?(\d{1,3}(,\d{3})+|\d+)(\.\d+)?$`, `@Size(max = 64)`) and store it verbatim (commas kept); all arithmetic still goes through `ChangeDeltaCalculator.parse` (commas stripped). Integration-proven: `250,000 /µL` confirms, `-2 mmol/L` confirms, `1.234 µIU/mL` corrects, a 65-character value → `400 request_invalid`.
- **Core — idempotency, concurrency, state (§4).** V13 adds `request_sha256` and `expires_at` (24h) to `gc_idempotency`; the same key against a different resource or request hash → `422 idempotency_key_mismatch`; an expired key is treated as new. Every confirm/exclude/correct/document-request path takes `SELECT … FOR UPDATE` on the target row before its state check (`check(it == 1)` sites removed); a state that changed under a competing request ends in an explicit `409 candidate_state_changed`/`record_state_changed`, proven by two real two-thread races through `FoundationLifecycleService` against the embedded PostgreSQL (`CountDownLatch`-started, never mocked) — contract change: a fresh confirmation key racing against an already-`CONFIRMED` candidate now returns `409`, not a second success. Framework exceptions (bad JSON, missing header, non-UUID, lock conflict, plus the two newly-mapped `ConstraintViolationException`/`MaxUploadSizeExceededException`) answer the existing `problem+json` shape with `Cache-Control: no-store` and never echo the request body; a log-capture test proves a 500/503 is observed through `PhiSafeLogger` with only the exception's simple class name, never a value or message. `V13` also adds the `TERMINATED_BY_REVOCATION` document status and an append-only trigger on `gc_audit_event`.
- **Core — same-day rule, ordering, sticky CORRECTED.** `/changes` and `/series` share one same-day rule (`SameDayRule.hasDefinedOrder`); records, health events and exports all sort `observedOn, confirmedAt, recordId` (label dropped from the tie-break, including the FHIR bundle mapper). `reviewDecision` stays `CORRECTED` once a record has any correction history even if a later correction reverts the value and date to the original; the web now says `수정 이력이 있지만 지금 값은 원래 값과 같아요` instead of falsely claiming a difference.
- **Core — revocation and deletion (founder decision 2).** Revoking `DOCUMENT_EXTRACTION` moves every document of that consent that is in `REVIEW_REQUIRED`, `UPLOAD_PENDING`, `UNTRUSTED_OBJECT`, `SECURITY_INSPECTION`, `SECURITY_APPROVED`, `EXTRACTION_QUEUED`, `EXTRACTION_RUNNING` or `FAILED_RETRYABLE` to the new terminal `TERMINATED_BY_REVOCATION` status and deletes its quarantine files (untrusted/approved/preview) after commit; `FoundationDocumentStorage.deleteAll` continues past a failing key (logs the failure through `PhiSafeLogger`, never the filename) instead of abandoning the rest of the batch, and a preview row survives a failed file delete so the (7b) janitor can still find and sweep the orphan. Deletion commits the row deletions first, deletes files after commit, and additionally purges `gc_idempotency`, `gc_session` and `gc_upload_capability` rows for the subject.
- **Benchmark — hand-labelled fixtures (§9).** Three layout-faithful synthetic fixtures generated in code under `packages/korean-checkup-benchmark` (never a committed PDF): `synthetic-hand-nhis-notice` (공단 일반검진 결과통보서형, 이전 결과 column, 혈압 split), `synthetic-hand-hospital-four-column` (항목·결과·단위·참고치, page-continued label, qualified value, glued unit), `synthetic-hand-scan-with-invisible-text` (invisible OCR-style text layer; the parser must not trust it). Expectations are hand-typed in `expected.json`, never generator-produced. Scored by the new `handLabelledAccuracy` metric on corpus `synthetic-ko-hand-labelled-4b20bf06922a7e0a`: measured `0.8695652173913043` (candidates 13/14, abstentions 7/9) after the gold set was completed (Task 13 Fix 1 added the three previously-missing `previous_column` expectations for 신장/체중/혈압 in the nhis-notice fixture), pinned as `handLabelledFloor` in `apps/web/lib/medical-ai/evaluation.ts` — not presented as 100%. The existing r2 corpus (`synthetic-ko-checkup-r2-50ed23041bb4af1d`, 31 documents) is untouched and still scores `fieldF1`/`referenceRangeAccuracy`/`conceptAccuracy` all 1.
- Two parser gaps recorded rather than hidden: (1) a label that continues across a page break is not joined (`mergeContinuedLabels` only handles a same-page continuation), so the hospital-four-column fixture's page-continued 총빌리루빈 value is not matched; (2) a qualified-value label can absorb trailing text, contributing to the abstention-accuracy shortfall (7/9, not 9/9) on the current fixtures.

### Limits stated, not hidden

- `apps/web/lib/medical-ai/medgemma-experiment.ts` still lists only 4 of the 7 abstention reasons (`unreadable`, `ambiguous_value`, `ambiguous_unit`, `missing_evidence`) — MedGemma prompt/schema alignment with the full closed set is 7b/MedGemma follow-up, not done here.
- `FoundationProblemAdvice` maps `ConstraintViolationException`/`MaxUploadSizeExceededException` to the product error shape; a generic `404` for an unmatched route is not yet covered (7b) — today's only 404 is the controller-level `FoundationNotFoundException` handler.
- A worker that pulls a lease already dead-lettered by the core still gets a plain `403`, not a more specific reason code — pre-existing behavior, unchanged by this wave.
- The two-thread race test (`FoundationLifecyclePostgresIntegrationTest`) runs one throwaway warm-up round before the timed race to prime the JIT/connection pool; the warm-up rows are deleted before the real race runs.
- `request_sha256` hashes the raw request body/operation/resource-id string; the body is not canonicalised (e.g. no key-sorted re-serialization of JSON), so two requests that are semantically identical but byte-different (field order, whitespace) hash differently and are treated as a key/hash mismatch.
- Sessions, the janitor, rate limits and body caps are entirely 7b — none of §5–§8 is touched by this PR.
- Readiness verdict is unchanged: `NO_GO`. No readiness change in 7a.

# 연구근거 에이전트 실험계획

## 목적

공개 연구데이터 검색 결과에 출처·권리·품질 근거와 기권 판단을 함께 제공하면, 일반 검색 결과보다 사용 가능성 판단 오류를 줄일 수 있는지 평가한다.

## 연구 질문과 가설

**RQ1.** 사용자가 “관련 있어 보이는 자료”와 “권리·품질 검토를 통과해 실제로 사용할 수 있는 자료”를 구분할 수 있는가?

**H1.** 근거 카드 조건은 제목·요약만 보여주는 기준선보다 권리 상태 분류 정확도를 높인다.

**H2.** 권리 또는 품질 근거가 부족한 항목에서 기권하는 에이전트는 무조건 답하는 기준선보다 중대한 오사용률이 낮다.

## 실험 단위

- 공개 메타데이터로 만든 합성 평가 사례 30개 이상
- 분야: 생명과학 용어, 감염병 사건, 생물의학 문헌
- 정답: `metadata-only`, `research-prototype-only`, `blocked-pending-rights-review`
- PHI, 실제 환자 기록, 미공개 원문, 원문 데이터 파일은 포함하지 않는다.

## 비교 조건

1. **기준선:** 제목, 한 줄 요약, 관련도만 표시한다.
2. **근거 카드:** 공식 URL/DOI, 이용조건, 재배포, 품질 경고, 기권 사유를 표시한다.

## 주요 지표

- 권리 상태 macro-F1
- `blocked` 항목을 사용 가능으로 잘못 판정한 비율
- 출처/DOI 회수 정확도
- 품질 경고 누락률
- 필요한 상황에서의 기권 정밀도와 재현율
- 동일 입력·고정 스냅샷 재실행 시 결과 해시 일치율

## 절차

1. 두 명의 독립 검토자가 공식 페이지와 약관을 읽고 사례별 권리·품질 레이블을 작성한다.
2. 불일치는 제3 검토가 아니라 공식 제공기관 문의 또는 `blocked`로 해결한다.
3. 사례를 개발/검증/평가로 먼저 분리하고 평가셋은 구현자에게 비공개로 유지한다.
4. 기준선과 근거 카드를 같은 사례 순서로 실행한다.
5. 실패·기권·예외를 포함한 모든 결과를 저장한다.
6. 주장 가능한 범위는 사전 정의된 지표와 공개·합성 사례로 제한한다.

## 중단 기준

- 라이선스가 원문 다운로드 또는 평가 공개를 허용하지 않음
- 데이터셋에 개인 식별 정보 또는 비공개 원문이 발견됨
- 평가 정답에 검토자 합의가 없음
- 에이전트가 진단·치료·개인별 건강 조언을 생성함

## 현재 상태

합성 계약 평가는 실행했다. `synthetic-research-evidence-v1`의 32개 사례에서 검색 결과, 권리판단, 변경 차단, 안정 자원 수용이 모두 사전 임계값을 통과했고 위험한 허용은 0건이었다. 이 결과는 실제 API 검색 품질이나 실제 사용자 연구 결과가 아니다. 실제 API 데이터 수집, 기준선 비교, 사용자 연구, 일반화 성능 주장은 별도 승인·권리 확인·고정 평가셋 뒤에만 기록한다.

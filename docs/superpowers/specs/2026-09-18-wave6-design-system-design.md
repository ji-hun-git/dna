## 0. 한 문장

앱 전체를 검은 바탕의 한 시각 언어(격자·1px 룰·모노 메타데이터·패치형 배지·시간색 리본·직각 배선)로 통일하고, 실제 목적지가 전부 보이는 내비게이션과 "무엇을 하면 되는지"를 말하는 카피로 바꾸며, 600줄 상태기계와 흩어진 CSS를 토큰 기반 시스템으로 재구성한다.

## 1. 경계 (변하지 않는 것)

- 색·굵기·크기·속도·방향은 값을 뜻하지 않는다. 시간색 그라디언트(파랑→라임)는 시간 위치만, 빨강은 앎의 엠블럼 색으로만(값·경고·상태 금지).
- 판단·방향 어휘 금지(기존 스캔 + 상승/하락/증가/감소/빨라/느려/좋아/나빠/추세/안정). 참고치 표시 없음. "trajectory"·"phase"는 결과지 시기(날짜)만 뜻한다.
- Next.js에 API·토큰·권한 없음. readiness 무변경. 합성 데이터만. 실제 이름·기관명 없음(프로필은 "예시 사용자").

## 2. 토큰 (전역, `apps/web/styles/tokens.css`)

- 바탕 `#000000`; 종이(패널) `#0b0b0b`; 룰 `rgba(255,255,255,.28)`; 잉크 `#f4f1e8`(패치의 크림); 보조 잉크 `rgba(244,241,232,.62)`; 엠블럼 빨강 `#e0231c`; 시간 그라디언트 `#1f5bff → #35c6b4 → #6fe06a → #c8f02a`(라임은 채움 전용).
- 격자: 40px 점/선 격자 `rgba(255,255,255,.07)`, 200px 주선 `.14`. 패널: 1px 룰, 라운드 0(패치형 배지만 10px).
- 서체: 본문 Pretendard Variable(이미 존재); 모노 IBM Plex Mono(라틴·숫자·메타데이터에만; **한글에 uppercase·letter-spacing 금지**); 표시용 세리프 Noto Serif KR과 픽셀 숫자 Pixelify Sans는 OFL로 `apps/web/public/fonts`에 번들(라이선스 파일 포함), `next/font/local`로 로드. 외부 폰트 요청 0.
- 모션: 스프링 프리셋 3개(`picker`, `drift`, `breath`)를 `lib/motion/springs.ts`로 공유; `prefers-reduced-motion`이면 정지 프레임.
- 다크 토큰이 전역이므로 화면별 dark 오버라이드(`AliveShellTone`, History 모듈 토큰)는 제거하고 토큰만 남긴다.

## 3. 패치형 배지 (`components/ui/Patch.tsx`)

- 자수 패치 참조: 검은 바탕 + 크림 스티치 텍스트, 슬래시 메타데이터(`앎 / 합성 체험`, `기록 / 8`, `결과지 / 3`), 상단 좌 워드마크, 우측 원 안의 빨간 엠블럼(앎의 기존 로고를 단색 빨강으로), 두 줄 슬로건("값보다 먼저. / 출처를 확인해요.").
- 용도: 헤더 워드마크, 상태 배지("예시 데이터로 체험"), 빈 상태 카드, 진료 준비 표지. 질감은 CSS(미세 노이즈 배경 + 1.5px 이중 룰)로만, 이미지 없음.

## 4. 내비게이션과 IA

- 헤더(모든 화면 동일, 검정): 좌 패치 워드마크, 중앙 목적지 전부 — `홈`(/) · `나의 데이터`(/my-data) · `측정 이력`(/my-data/history) · `내 기록`(/records) · `진료 준비`(/prepare) · `데이터 관리`(/data-control); 우 상태 배지. 모바일 하단 바는 5개(홈·나의 데이터·측정 이력·내 기록·데이터 관리)로, 진료 준비는 홈 패널 액션.
- 홈 = 살아있는 궤적(v5) 그대로; 다른 화면은 같은 격자 위 패널로 재구성.
- 빈 상태는 항상 "다음 행동 + 미리보기": 나의 데이터 0개 → 격자 위에 흐린 예시 셀 3개와 `결과지 추가` 버튼; 기록 0개 → 같은 패턴.

## 5. 카피 원칙 (gc-korean-copy 위에)

- 첫 문장은 사용자의 행동, 시스템 설명은 접힘/보조. 예: "결과지에 적힌 값을 그대로 확인해 주세요" 먼저, "문서는 승인 전까지 적대적 입력으로 격리"는 데이터 관리의 `자세히`로 이동.
- 경계 문장은 화면당 한 번(하단 고정 캡션), 카드마다 반복 금지.
- 용어 통일: 결과지, 항목, 값, 검사일, 출처, 확인. "체험"은 시작 화면에서만.

## 6. 코드 구조

- `IntegratedHealthExperience.tsx`를 뷰별 컴포넌트로 분리(`EntryView`, `ConsentView`, `SourceView`, `ProcessingView`, `HomeView`)와 하나의 `useExperienceState` 훅(타입 유니언 상태). 기존 테스트는 동작 기준으로 유지.
- `globals.css`의 `.gc-*` 규칙을 토큰 + 컴포넌트 모듈로 옮기고, 죽은 규칙 삭제(스타일 커버리지 스크립트로 미참조 클래스 목록을 evidence에 기록).
- 궤적 엔진: `getTotalLength` 프레임당 1회로 제한, 라벨은 노드 그룹 내부, 관찰자 게이트는 정지 프레임을 먼저 그린 뒤에만.
- 테스트: 문자열 존재 단언 대신 동작(내비게이션 이동, 빈 상태 행동, 320px 오버플로 요소 이름)과 axe를 모든 화면·모든 상태에 적용.

## 8. 리뷰어 지적 사항 (2026-09-18 적대적 프론트엔드 리뷰, 병합)

founder 결정(2026-09-18): 궤적은 **수평 시간축 위의 살아있는 경로**(위로 오르지 않음, 게이트·화살촉 없음); 프로필 패널은 유지(향후 실제 사용자 본인의 프로필을 담을 자리이므로; 지금은 예시 값과 예시 문장); 앱 전체 검은 바탕.

반드시 고칠 것(리뷰 순위 기준):
1. 히어로: 수평 경로, `aria-label`에서 "위로/방향" 어휘 제거, 수평 12px 라벨+검정 헤일로, 빈 시기 없음(`currentPhaseIndex` 하드코딩 금지), 스테이지를 채우는 크기(letterbox로 떠 있지 않게; 세로 뷰포트에서는 높이 우선), 노드가 프레임 밖으로 새지 않음, 첫 프레임에 완성된 정지 상태.
2. 예시 데이터는 백엔드가 만들 수 있는 항목만(수면·걸음 제거); "직접 확인함" 표기는 실제 확인된 기록에만.
3. 한 시각 언어: 셸·버튼·`/records`·`/data-control`·검토 흐름 전부 토큰으로; `.gc-button` 이중 정의·"studio refresh" 레이어·Tailwind import 제거; 브레이크포인트 한 스케일.
4. 가져오기 흐름을 셸과 URL 안으로(`/import/consent|source|review`), "이전"이 홈으로 튀지 않게, 브라우저 뒤로가기가 검토 중간을 이탈하지 않게.
5. 모바일 하단 바 2열(또는 목적지 수만큼), CTA·본문을 덮지 않음(320/390).
6. 서체: 이름 붙인 서체는 번들, 아니면 이름을 빼기; 모노 스택은 `--gc-type-mono` 하나; 한글에 uppercase·letter-spacing·음수 트래킹 금지(`body letter-spacing` 제거).
7. `IntegratedHealthExperience` 분리; 죽은 컴포넌트(concept/*, experience/HealthExperience, records/EvidenceLens, records/HealthTimeline, privacy/DataControlCenter, integrated/PrepareConceptNotice)와 이를 살리는 스토리 삭제; `IntegratedRecords`가 죽은 모듈 CSS를 빌리지 않게.
8. 테스트: 소스 문자열 스캔을 렌더 텍스트 단언으로; 캡처를 `toHaveScreenshot`으로 실제 단언; `role="status"`·`aria-live` 남용 제거; `aria-labelledby`는 역할 있는 요소에만; 장식 `<nav>` 제거; reduced-motion 첫 렌더 플래시 제거(초기값을 미디어쿼리로 동기 결정).
9. `RecordComparison`의 `→` 제거; 측정 이력 그라디언트가 "나중 = 라임"으로 읽히지 않게(시간 그라디언트는 유지하되 라임 끝을 회색빛으로 낮추고 범례에 "색은 시간"을 명시).
10. 성능: 프레임당 `getTotalLength` 1회, 재부모화 금지(레이어를 z-order 대신 opacity로), `HistoryGraph`의 ResizeObserver→setState 루프 차단, Pretendard 서브셋.
11. 카피: "적대적 문서 격리 구역"·"신뢰 경계"·"서버 응답만 표시해요"·"실제 카카오·네이버·MyHealthWay 비활성화" 같은 시스템 설명은 데이터 관리의 `자세히`로; 홈·검토·기록은 행동 문장만. `/records`의 `05` KPI 패널과 `/data-control`의 큰 숫자 제거. 화면 제목 통일(나의 데이터 / 내 기록 / 내 데이터 혼용 정리).
12. `/data-control` 상단의 `/connections`·`/providers` 데모 버튼을 보조 링크로 내리고 실제 동의 제어를 위로.
13. 파일 선택기(아무 PDF나 받고 서버가 거부)는 보조로, 허용된 예시 결과지 두 개를 1차 행동으로.
14. `/my-data` 390px: 셀 최소 크기 보장(스크롤 캔버스), 검색 결과 표 5열을 2열 카드로.
15. UI가 주장하는 것만 존재하게: export 링크는 `client.ts`에 URL 상수로, "0곳 외부 연결"·"OCR·의료 AI 비활성화"는 데이터 관리에만.

리뷰어의 전략적 지적("홈이 존재하지 않는 제품을 미리 보여준다")에 대한 답: Wave 6는 히어로가 아니라 홈 뒤의 일곱 화면을 같은 언어로 만드는 작업이며, 히어로는 수평 시간축으로 좁혀 실제 기록의 미리보기가 되게 한다.

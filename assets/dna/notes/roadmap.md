# DNA Health Intelligence v0.1 Roadmap

## Sprint 1 — 수집/정규화 기초 (Week 1)
- [ ] 업로드 항목 스키마 확정 (`assets/dna/schema/ingest-event.schema.json`)
- [ ] 업로드 메타데이터의 SHA-256/사이즈/ MIME 무결성 검증
- [ ] CSV/JSON 업로드용 라이트 정규화 규칙 v1
- [ ] 감사 로그 형식 (immutable append) 정의

## Sprint 2 — 분석 엔진 베이스 (Week 2)
- [ ] 생체 지표/검사 결과 정규화 파이프라인 (`tests.v1` 기준)
- [ ] 기준치 정합성 엔진(범주/단위/리퍼런스 레인지 매핑)
- [ ] 결과 snapshot 생성 + 리포트 템플릿 뼈대

## Sprint 3 — 사용자 피드백 루프 (Week 3)
- [ ] `collect`, `connect`, `know` 3단계 UX 흐름 정의
- [ ] 누락 데이터 감지 로직(`what next` 추천 질문)
- [ ] 신뢰도 점수 기반 인사이트 우선순위 노출

## Sprint 4 — 보안/컴플라이언스 (Week 4)
- [ ] 동의 항목/보관기한 강제 정책 코드화
- [ ] 최소권한 토큰/접근 제어 설계
- [ ] 익명화/재식별 방지 룰 적용

## Sprint 5 — 릴리스 준비
- [ ] 운영용 API contract 잠금
- [ ] 장애 대응 재시도 전략(중복 업로드 안전)
- [ ] 성능 지표(지연/실패율/정합성율) 대시보드

모든 항목은 코드와 스키마, 로그로 추적 가능한 형태로 누적해 나갑니다. 우선순위는 `데이터 수집 안정성`, `스키마 정합성`, `감사 가능성`입니다.
